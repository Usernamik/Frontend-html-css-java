Challenge 1. Flexbox: responsive header

  1. Розташуйте logo, navigation та button в одному рядку.
  2. Забезпечте вертикальне вирівнювання.
  3. Задайте відстань між елементами через gap.
  4. Дозвольте navigation переноситися на новий рядок.
  5. Не використовуйте position: absolute для побудови layout.
  6. Перевірте поведінку при вузькому viewport.

Додатково: при недостатній ширині navigation автоматично переходить на наступний рядок — без Media Query.

Очікуваний результат: header залишається працездатним при різній ширині viewport.

Challenge 2. Grid: adaptive card layout

  • картки мають мінімальну ширину 220px;
  • кількість колонок залежить від доступного простору;
  • між картками однаковий gap;
  • немає горизонтального overflow;
  • без окремих Media Queries для 2, 3 та 4 колонок.

Використати: repeat(), minmax(), auto-fit.

Експеримент: порівняйте repeat(auto-fit, minmax(220px, 1fr)) і repeat(auto-fill, minmax(220px, 1fr)) та поясніть різницю за результатом. Різницю видно, коли в рядок поміщається більше колонок, ніж є карток: розширте viewport або тимчасово приберіть кілька карток.

Challenge 3. Responsive page layout: Grid + Flexbox

Побудуйте повний layout сторінки: на desktop — ліворуч, на вузькому viewport — праворуч.

  +-------------------------------+      +-----------------+
  |            Header             |      |     Header      |
  +---------+---------------------+      +-----------------+
  | Sidebar |        Main         |      |      Main       |
  +---------+---------------------+      +-----------------+
  |            Footer             |      |     Sidebar     |
  +-------------------------------+      +-----------------+
                                         |     Footer      |
                                         +-----------------+
  • Grid — для загального page layout та sidebar + main.
  • Flexbox — для header, navigation і групи кнопок .actions.
  • Breakpoint визначте самостійно або, якщо це можливо, реалізуйте зміну layout без Media Query.

Не використовувати: float; таблиці для layout; абсолютне позиціонування як основний layout-механізм; фіксовану ширину всієї сторінки.

Challenge 5–6. Container Query: reusable Card

Та сама .product-card стоїть у трьох місцях: у .sidebar, у main і в modal-like контейнері .modal.

Challenge 5

  1. Побудуйте layout .content-layout (sidebar + main) і обмежте ширину .modal, щоб отримати три контейнери різної ширини.
  2. У вузькому контейнері картка — вертикальна, у широкому — зображення й текстовий блок в один ряд.
  3. Не використовуйте @media для зміни layout картки: задайте container-type обгортці .card-wrapper і використайте @container.
  4. Перевірте, що кожна картка адаптується незалежно від viewport: змінюйте в DevTools ширину контейнера, а не вікна.

Додатково: реалізуйте іменований container — container: card / inline-size;.

Challenge 7. Fluid Typography

style.css містить breakpoint-based typography: окремий font-size для кожного breakpoint. Замініть його на fluid typography через clamp(); конкретні значення підберіть самостійно.

  • текст не стає надто малим і не стає надто великим;
  • розмір змінюється плавно, без окремого breakpoint для кожного розміру тексту.

DevTools experiment: змінюйте ширину viewport, виберіть h1, відкрийте Computed і зафіксуйте фактичний font-size щонайменше для трьох значень ширини.

AI-агент тут виступає у двох ролях: спочатку генерує рішення, потім перевіряє його як reviewer. Між цими етапами ви перевіряєте код самостійно.

Етап 1. Генерація. Отримайте від AI-агента CSS-рішення для такого завдання:

Create a responsive dashboard with a header, sidebar, main content area and a grid of cards. It should work on desktop, tablet and mobile.

Challenge 10. Final Responsive Component

Об'єднайте отримані навички в одному компоненті — Responsive Feature Section: на desktop картки стоять у ряд, на mobile — одна під одною.

Обов'язково використати:

  • CSS Grid;
  • Flexbox щонайменше для одного внутрішнього компонента;
  • minmax() або auto-fit;
  • clamp();
  • Container Query щонайменше для одного компонента;
  • DevTools для перевірки responsive behavior.

Необов'язково: subgrid; container query units; named containers.

Вимоги (§6): без горизонтального overflow, без фіксованої ширини основного контейнера, без зайвих breakpoint-ів, без overflow-x: hidden для приховування проблем і без абсолютного позиціонування як основного механізму layout.
